## 架构概览

```
cli.py ──→ voyage.py ──┬──→ config.py    (YAML 配置 + plan.yaml)
                        ├──→ state.py     (SQLite 持久化)
                        ├──→ map_engine.py(地图引擎)
                        ├──→ crew.py      (船员系统 — 招募/对话/情绪/被动成长)
                        ├──→ llm.py       (AI 日志 + 教练 + 计划 + 史诗)
                        └──→ events.py    (随机事件)
```

五层：展示层（cli.py + _views.py）→ 逻辑层（voyage.py）→ 子系统（crew.py + map_engine.py + events.py）→ AI 层（llm.py）→ 数据层（state.py + config.py）

渲染层独立：`renderers/` 目录（ASCII + Canvas/PNG/Kitty），不耦合业务逻辑。

## 关键设计决策

1. **核心体验是叙事，不是养成** — 船员不是"升级打怪"的对象，是陪伴者和叙事参与者
2. **升级被动、不花金币** — 等级随相处时间自然增长，上限 5 级，感知点在对话深度和史诗篇幅
3. **情绪仅三档** — 只影响语气，不做精确数值追踪，不制造焦虑
4. **角色和人设分离** — role 是职能，character 是性格和故事，同一 role 可有多个人设
5. **饮食管理集成到厨子** — 不独立成系统，厨子是低价船员
6. **里程碑史诗是 LLM + 事实注入** — 第三人称编年史，基于真实航行数据
7. **砍掉每周任务** — 任务系统给用户压力，和陪伴感冲突
8. **商店不独立成版本** — 消费出口和船员系统集成（招募/人设/召回）
9. **船长免费** — `bestman talk` 始终可用，训练计划通过船长对话完成
10. **地图短期不动** — Canvas 渲染系统已经够好，动态地图排 v3.0
