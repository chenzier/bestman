# Android Agent 化手机版技术路线

> 状态：规划，尚无 Android 客户端
> 定位：Agent 化宠物船陪伴；船长、吟游诗人等角色与用户对话，前端呈现台词和动作

## 产品与实现边界

Bestman 手机版不是 CLI/TUI 的缩小版，也不是在健身 App 旁边加一个通用聊天窗口。宠物船占据首页，角色是用户理解、回应与陪伴的入口；对话可以驱动前端的表情、动画和叙事，但模型输出不直接成为金币、体重或打卡事实。

Android 首版以 [Arxd](https://github.com/TsingShui/Arxd) 为候选应用底座，复用模型连接、流式对话、持久化与任务恢复。先在 fork 中验证和改造，不把 Agent 拆成独立包作为前置任务。Arxd 的逆向提示词、工具与页面不是 Bestman 的需求，应替换或收起；自定义角色不能只是叠加在旧静态分析设定上。首版不要求 MCP、Termux 调用 Bestman CLI 或本地 GGUF 模型；这些是后续按真实需求评估的可选能力。

现有 Rust CLI/TUI 保持可用。手机首版先验证角色对话，不为了它提前重构全部 Rust 核心；当手机端需要真实打卡、计划和体重记录时，再决定 App 内调用 Rust 规则与事件的方式，或设计兼容的数据接口。不在 Android 端重新发明一套奖励与打卡规则。

## 分阶段交付

### 1. 角色与界面原型

- 制作电脑浏览器可查看的宠物船界面原型，展示角色选择、台词、待机与回应动作。它只验证视觉和交互，不代表 Android 原生 Agent 已可运行。
- 船长与吟游诗人先共用一套 Agent 运行时，各自拥有身份、语气、对话历史；不预设多个 Agent 相互协作。
- 前端控制角色、表情与动画的呈现；可从现有 spritesheet 和 manifest 取视觉资产，不移植终端图片协议或 dashboard PNG。

### 2. Android Agent 闭环

- 在 Arxd fork 中替换产品身份、默认指令和逆向专属的安全描述，保留通用的凭据保护与真实工具结果约束。
- 验证模型配置、角色切换、流式回复、会话隔离、切换前后台及进程重启后恢复；记录每个角色能看到的用户背景和共享记忆边界。
- 角色回复可以附带受约束的情绪/动作意图；非法或缺失时由前端回退到默认动作，不让模型直接控制渲染或改核心状态。
- 通过 Android 开发构建在模拟器或真机验收；浏览器原型不能替代这一步。模型离线能力须单独验证，不能把“端侧 App”当成“离线推理”。

### 3. Bestman 真实行为

- 优先接入查询状态与运动补记，再接计划、休息和体重；为重复提交、任务恢复和失败重试设计幂等语义。
- 行为经用户确认和确定性规则校验后写入事实记录；Agent 负责理解与叙事，不直接写 `events.jsonl`、SQLite 或发奖励。
- 现有事件历史必须可重建；明确移动端的本地存储、迁移与将来跨设备同步策略。网络或模型不可用时，真实记录不能丢失。

### 4. 后续扩展

- AI 训练计划先给可编辑建议，经确认才执行；拍照饮食保留估算、来源与人工修正。见 [plan.md](plan.md) 与 [diet.md](diet.md)。
- 推送、账户、同步、复杂船员养成和市场不阻塞首版角色陪伴体验。

## 首版验收

- 用户可选择船长或吟游诗人进行连续对话，角色身份与语气稳定，历史不会意外串到另一个角色。
- 回复逐步显示，宠物船有可区分的待机与回应动作；减弱动效时仍可读。
- Android App 关闭重开后能恢复对话；模型故障给出真实错误或重试，不编造已完成操作。
- 逆向专属文案、入口和工具不会混入 Bestman 对话；首版不宣称已经支持真实打卡或离线模型。
