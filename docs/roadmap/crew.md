# 船员/角色技术路线

> 优先级：远期  
> 定位：叙事扩展，不是 v1 主线

## 新定位

旧路线把船员系统设计成 v2 主功能，包括招募、升级、人设、港口、厨子、队医等。当前方向下这会过早稀释宠物船体验。

现阶段结论：

- v1 不做复杂船员系统。
- 船员不是核心养成对象。
- 如果未来加入，应该服务宠物船叙事，而不是替代宠物船。

## 可保留的设计原则

- 角色和人设可以分离。
- 对话应强调陪伴感，不做强数值养成。
- 情绪不要做复杂 0-100 细分。
- 不做每周任务和 XP grind。
- LLM 对话必须有 template fallback。

## 未来可能形态

### 轻量角色

先从“船旁角色”开始，而不是完整 crew 系统：

| 角色 | 功能 |
|------|------|
| 船长 | 训练计划调整、日志语气 |
| 厨子 | 饮食记录反馈 |
| 队医 | 伤病/体重反馈 |

这些角色可以是叙事 voice，不一定要有招募、等级、装备。

### 数据边界

如果实现，必须仍遵守：

- 规则系统拥有状态。
- LLM 只生成对话。
- 船员不能直接改金币/位置。
- 船员状态从事件重放可恢复。

## 暂缓内容

以下旧设计暂缓：

- 船员招募/解雇/召回。
- 船员 XP 和升级。
- 港口系统。
- 每周任务。
- 复杂 persona YAML 工坊。
- 船员随机扭蛋。

这些内容只有在宠物船 v1/v1.2 稳定后才重新评估。
