# 船员/角色技术路线

> 优先级：对话角色进入 Android 首版；复杂船员养成远期
> 定位：Agent 化陪伴角色，服务宠物船叙事

## 新定位

旧路线把船员系统设计成 v2 主功能，包括招募、升级、人设、港口、厨子、队医等。当前先做可对话的角色，而不是数值化船员系统；详见 [Android 路线](mobile.md)。

现阶段结论：

- Android 首版提供船长和吟游诗人等对话身份，共用 Agent 运行能力，不预设多 Agent 协作。
- 不做招募、升级或复杂船员系统；角色不是核心养成对象。
- 对话服务宠物船叙事，不替代宠物船。

## 可保留的设计原则

- 角色和人设可以分离。
- 对话应强调陪伴感，不做强数值养成。
- 情绪不要做复杂 0-100 细分。
- 不做每周任务和 XP grind。
- LLM 对话必须有 template fallback。

## 首版角色与后续扩展

### 轻量角色

先从“船旁角色”开始，而不是完整 crew 系统：

| 角色 | 功能 |
|------|------|
| 船长 | 日常陪伴、运动后的温和反馈；后续可讨论训练计划 |
| 吟游诗人 | 航海故事、行动回顾与叙事陪伴 |
| 厨子（后续） | 饮食记录反馈 |
| 队医（后续） | 伤病/体重反馈，不做诊断 |

这些角色先表现为各自的人设、对话历史和界面呈现，不需要招募、等级或装备。首版不承诺能修改真实打卡记录。

### 数据边界

真实行为接入时必须仍遵守：

- 规则系统拥有状态。
- Agent 可以生成对话和建议，不能直接改金币、位置或打卡事实。
- 角色对话由 Agent 持久化；后续进入规则系统的业务状态必须可由事件重放恢复。

## 暂缓内容

以下旧设计暂缓：

- 船员招募/解雇/召回。
- 船员 XP 和升级。
- 港口系统。
- 每周任务。
- 复杂 persona YAML 工坊。
- 船员随机扭蛋。

这些内容只有在 Android 角色陪伴与宠物船主体验稳定后才重新评估。
