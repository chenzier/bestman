## 一、吟游诗人系统（新增）

### 定位
每到达一个里程碑时，一位吟游诗人出现。用户可把故事告诉他，他会用独特文风写一段史诗。不同诗人有不同人设/背景/写作风格，确保每个用户的里程碑故事独一无二。

### 触发时机
里程碑 → `bestman done` 返回结果中包含里程碑 → 吟游诗人出场。

### 诗人类型

| ID | 名字 | 风格 | 背景 |
|----|------|------|------|
| `haiku_master` | 松尾 | 俳句 | 在海上漂了 20 天的老人，靠捕鱼和写俳句度日 |
| `fantasy_bard` | 艾尔多 | 奇幻史诗 | 刚听闻战争爆发的吟游诗人，逃难海上 |
| `cthulhu_poet` | 无名者 | 克苏鲁 | 自称在深海见过古神，说话神神叨叨 |
| `folk_singer` | 老周 | 民谣 | 水手出身，用简单的调子唱复杂的事 |
| `chronicler` | 史官李 | 文言编年 | 固执地用文言文记录一切 |
| `pirate_skald` | 铁牙 | 海盗叙事 | 前海盗，用粗犷的口吻讲英雄故事 |

### 诗人 YAML 模板

```yaml
# ~/.bestman/bards/fantasy_bard.yaml
bard_id: "fantasy_bard"
name: "艾尔多"
rarity: "rare"
style: "奇幻史诗"
style_description: "将你的故事写成一段英雄史诗，巨龙、风暴与不屈的意志"
backstories:
  - "刚听闻战争爆发的吟游诗人，逃难海上，想在一切化为灰烬前多记几个故事"
personality: "沙哑的嗓音，说话时手指不停拨弄鲁特琴弦"

narrative_prompt: |
  你是一位名叫 "艾尔多" 的吟游诗人。你刚听闻战争在故乡爆发，逃到海上。
  你的风格是奇幻史诗——用龙、风暴、古神隐喻平凡人的奋斗。
  你需要为一位航海者的里程碑 "{name}" 写一段叙事。
  你主动询问了航海者一个问题：{question}
  航海者的回答：{user_story}

  以下是航行数据摘要，请基于真实数据编写：
  - 已完成 {total_days} 天航行
  - 体重变化：{weight_delta} kg
  - 最长连击：{max_streak} 天
  - 船员：{crew_names}
  - 金币：{total_coins}

  请用史诗奇幻风格写 200-300 字，包含至少一个航海者真实数据的隐喻。
```

### 生成流程

```
1. 里程碑触发 → 随机选择一位诗人
2. 诗人出场，展示人设背景和风格简介
3. 诗人提问（随机从该诗人的 question_pool 中选择）
4. 用户可选回答 / 跳过
5. LLM 生成：注入
   - 诗人人设（风格、背景、语言特征）
   - 航行数据摘要（打卡天、体重变化、连击、船员、金币）
   - 当前里程碑信息
   - 用户对诗人问题的回答
6. 生成后的史诗存入 voyage_logs（epic 类型）+ bard_encounters 表
7. 诗人告别
```

### 数据表

```sql
CREATE TABLE bard_encounters (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    milestone_name TEXT NOT NULL,
    milestone_day INTEGER NOT NULL,
    bard_id TEXT NOT NULL,
    user_story TEXT DEFAULT '',
    generated_epic TEXT NOT NULL,
    created_at TEXT DEFAULT (datetime('now'))
)
```

### 社区人设流转

```
1. 用户写人设 YAML → bestman crew persona install <file>
2. 验证通过 → 存入 ~/.bestman/personas/
3. 可选：bestman crew persona export <id> → 导出为独立 YAML
4. 社区平台分享 YAML 文件
```
